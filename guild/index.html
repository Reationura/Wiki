Guild Wiki — 总览

功能全面的 Minecraft 公会管理插件 · 当前版本 v3.0.8

Guild 是一款功能全面的 Minecraft 公会管理插件：GUI 可视化操作 / 等级经验 / 银行 / 商店 / 聊天频道 / 多货币 / 多语言 / 开发者 API。

插件版本 3.0.8 ｜ 配置文件版本 1.3 ｜ 作者 ya_xzer21145

功能亮点

  • 🏰 完整公会体系：创建、入会申请、邀请、离开、解散、踢出、晋升 / 降级、会长移交、重命名
  • 🖥️ GUI 可视化操作：主界面 / 公会列表 / 银行 / 管理 / 成员设置 / 商店六大界面，支持铁砧与聊天框两种输入方式，无需记忆命令
  • 📊 等级与经验系统：击杀怪物、挖掘方块、钓鱼、繁殖、交易、附魔、PVP 等 13 种行为均可产出公会经验，等级公式与上限全部可配置
  • 🏦 银行系统：与玩家钱包真实打通的存取款，支持限额、税率、每日限额、职位权限、交易记录
  • 🛒 公会商店：shop.yml 自定义商品，按公会等级解锁，支持发放命令 / 物品 / 经验 / 公会币等 5 种动作
  • 💰 多货币支持：内置公会币（持久化落库）/ Vault 经济 / PlayerPoints 点券，一处配置全局切换
  • 💬 聊天频道：公会频道 + 管理频道，格式完全配置化
  • 🏷️ 标签与公告：公会标签（含颜色代码白名单）、MOTD 公告、成员昵称
  • 👥 三级角色权限：会长 OWNER / 管理员 OFFICER / 成员 MEMBER，guild.yml 支持按功能键设置所需最低职位
  • 📱 上下线通知：按玩家个人设置开关，可在 GUI 中自由切换
  • 🌐 多语言：内置简体中文（zh_cn）、繁体中文（zh_tw）、英文（en_US）三套语言包
  • 📈 排行榜：今日贡献排行、公会等级总览
  • 💾 SQLite / MySQL 双数据库：HikariCP 连接池，事务写入
  • ⚡ 高性能：全异步保存队列、玩家名缓存、异步数据库 I/O，主线程零阻塞

安装与快速开始

  1. 将 Guild-3.0.8.jar 放入服务器 plugins/ 目录
  2. 启动服务器，插件自动生成全部配置文件与语言包
  3. 按需修改 plugins/Guild/ 下的配置（每个文件顶部都有注释说明）
  4. 修改后执行 /guild reload 重载，无需重启服务器
  5. 玩家进服即用：/guildgui 或 /guild 打开主界面

首次启动会执行数据库迁移检查；若 config.yml 的 config-version 低于插件内置版本（当前 1.3），控制台会提示，新配置项自动使用默认值。

核心功能详解

本页介绍 Guild 的完整功能体系。配置项细节见 配置文件与数据库。

1. 公会生命周期

环节说明
创建 /guild create <名称> [标签] 或 GUI 内点「创建公会」→ 聊天框 / 铁砧依次输入名称与标签。名称受长度（min/max-name-length）、正则（name-regex）、黑名单（banned-names）三重校验；创建费由 currency.yml 统一扣取（create.requires-money + create.cost）
入会申请 /guild join <公会名> 提交申请，会长 / 管理员在 GUI「批准 / 拒绝」；申请 10 分钟自动过期
邀请 /guild invite <玩家>，受邀玩家 /guild accept / /guild decline；邀请 10 分钟过期，受邀者可在个人设置关闭邀请接收
离开 /guild leave，普通成员直接退出（需输入 confirm 确认）；会长离开等于解散公会
踢出 /guild kick <玩家> 或 GUI 成员操作。3.0.8 起强制角色保护：不能踢自己、不能踢会长、非会长不能踢同级或更高级成员
解散 /guild disband（聊天确认），或管理员 /guild delete <公会名>（二次 confirm）。解散会清理成员索引、指向该公会的邀请，并异步删除数据库记录
重命名 /guild rename <新名称> 或 GUI「重命名」。原地迁移全部成员 / 等级 / 经验 / 银行 / 权限数据（3.0.7 起取代旧「解散重建」实现），仅会长可用，校验与创建一致

2. 角色与权限体系

  • 三级角色：MEMBER(1) → OFFICER(2) → OWNER(3)
  • 晋升 / 降级：/guild promote|demote <玩家> 或 GUI 成员设置界面；已到顶 / 到底时操作返回失败（3.0.8 起不再误报成功）
  • 会长移交：/guild transfer <玩家>
  • 公会内权限门槛：/guild permission <权限键> <等级> 可逐项设置该操作需要的最低职位（1=成员 2=管理员 3=会长），修改实时落库。常用权限键：kick、invite、chat、motd、settings、promote 等
  • GUI 根据角色展示不同按钮（会长见「管理公会 / 升级公会 / 购买经验」，管理员见「管理公会」）

3. GUI 界面

界面打开方式内容
主界面/guildgui 或 /guild公会信息、成员列表（头骨展示）、银行 / 商店入口、邀请与通知开关
公会列表主界面「查看所有公会」全部公会按等级排序展示
银行界面/guildgui bank 或主界面「公会银行」余额展示、存入 / 取出（聊天输入金额）、交易记录
管理界面主界面「管理公会」（会长 / 管理员）重命名、更改标签、解散引导
成员设置点击成员头骨设置昵称、晋升 / 降级、踢出（按权限显示）
商店界面主界面「公会商店」shop.yml 商品展示、等级锁定提示、点击购买

所有界面均可拖拽防泄漏（取消点击 / 拖拽 / 移动事件），标题与物品外观由 gui.yml 配置。

4. 等级与经验系统

经验获取（experience.yml → events，0 = 关闭该项）

行为默认经验行为默认经验
击杀怪物10村民交易20
挖掘方块5附魔12
放置方块3合成5
PVP 击杀50酿造6
钓鱼8熔炼4
繁殖15驯服10
达成成就30（均为默认值，可任意调整）

防刷与限制

  • 防刷屏：no-exp-blocks / no-exp-mobs 黑名单方块与实体不给经验
  • 升级公式：base × level × (1 + level × growth-rate)，level-formula 支持 max-required 封顶
  • 成员上限：base-members + level × members-per-level
  • 等级上限：max-level（guild.yml）
  • 加成与限制：周末倍率、节假日倍率、每日经验上限、每日贡献上限（增量截断而非整单拒绝）
  • 每日重置：跨天自动重置日常经验 / 贡献与银行每日限额（features.yml → daily-reset）
  • 升级事件：自然升级与付费升级均触发 GuildLevelUpEvent（3.0.8 起全路径恰好一次）

管理员干预与付费途径

  • 管理员命令：/guild gexp（给经验）、/guild slevel（设等级）、/guild clxplev（清零）
  • 付费途径：GUI / 命令「购买经验」按 currency.yml experience-cost/amount 消耗货币；「升级公会」按 level-up-cost × (1 + level × 0.08) 扣费

5. 银行系统

  • 存款 /guild deposit <金额>，取款 /guild withdraw <金额>，查询 /guild balance，或 GUI 银行界面
  • 与玩家钱包真实打通：存款先扣玩家货币、取款后入账玩家货币，任一环节失败自动回滚，杜绝凭空造币
  • bank.yml 全面生效：单次存 / 取上限、银行余额上下限、存 / 取税率（按比例折算实际到账）、每日存 / 取限额（跨天重置）、最低职位限制（withdraw-permission: OFFICER 默认取款需管理员）
  • 每位玩家保留最近 50 条存取记录（GUI 可查），大额交易写控制台日志
  • 整体开关：features.yml → bank，关闭时命令直接拒绝

6. 货币系统（currency.yml）

类型说明
GUILD_COIN 内置公会币（默认）。独立持久化于 player_currency 表，重启不丢；支持 initial-balance 进服发放（数据库行存在性保证终生一次）、max-balance 上限截断
VAULT 对接 Vault 经济（需安装 Vault + 前置经济插件）
PLAYERPOINTS 对接 PlayerPoints 点券（反射调用，无需硬依赖）

type 决定创建 / 升级 / 购买经验扣除的货币；商店商品可在 shop.yml 逐件指定货币。显示名称与千分位格式化均可配置。

7. 公会商店（shop.yml）

每件商品字段：slot / material / name / lore / required-level / price / currency-type / action / action-value / buy-message / permission。

支持 5 种购买动作：

action效果action-value 示例
COMMAND以玩家身份执行命令home set（支持 %player%）
CONSOLE以控制台身份执行命令give %player% diamond 3
GIVE_ITEM直接给物品DIAMOND:3（材质:数量）
GUILD_EXP给公会加经验200
GUILD_COIN给玩家发公会币500

未到等级商品显示为「[锁定]」样式；购买按件校验公会等级、权限与余额。

8. 聊天频道

  • /guild chat <消息> 或 /guildchat <消息>（别名 /gc、/guildc）：公会频道
  • /guild officerchat <消息>：管理频道（仅会长 / 管理员可见）
  • 格式配置化（guild.yml）：chat.format 支持 {tag_color} {tag} {player} {message}；chat.officer-format 支持 {player} {message}
  • 发言受公会内 chat 权限与禁言状态约束；被 /guild mute 禁言的成员无法发言

9. 标签、公告与通知

  • 标签：/guild tag <标签> + /guild tagcolor <颜色代码>（受 allowed-tag-colors 白名单限制），GUI 亦可修改
  • 公告：/guild motd <内容>（≤100 字符），在 /guild info 与 GUI 展示
  • 昵称：会长 / 管理员可为成员设置公会昵称（GUI 成员设置 → 设置昵称，输入 C 取消）
  • 上下线通知：成员进服 / 退服时向开启了通知的同会玩家广播；个人开关可通过 GUI「上下线通知」按钮或 /guild settings 调整
  • 禁言：/guild mute <玩家> <分钟> / /guild unmute <玩家>（3.0.8 起：分钟数必须 > 0，不能禁言会长或同级 / 更高级成员，禁言到期时间真实持久化）

10. 多语言

config.yml → language: zh_cn | zh_tw | en_us。三款语言文件释放于 plugins/Guild/lang/，可自由修改文案（YAML 格式，支持 & 颜色代码）。/guild reload 后生效。

核心功能权限节点PAPI 变量常见问题

权限节点

权限树采用 children 继承设计，配合权限插件（如 LuckPerms）按需下放即可。

权限节点说明默认
guild.*全部权限op
guild.admin管理权限集合（创建 / 邀请 / 踢出 / 升降级 / 解散 / 升级 / 银行 / 管理 / 设置 / 聊天）op
guild.player基础玩家权限（聊天 / 信息 / 商店）所有人
guild.create创建公会op
guild.invite / guild.kick / guild.promote / guild.demote邀请 / 踢出 / 晋升 / 降级op
guild.disband / guild.upgrade解散 / 升级公会op
guild.bank使用银行所有人
guild.chat公会频道发言所有人
guild.manage管理公会设置（重命名 / 标签 / MOTD）op
guild.settings修改个人设置所有人
guild.info / guild.shop查看信息 / 使用商店所有人

两层权限体系：Bukkit 权限节点（决定玩家能否使用某功能）与公会内职位门槛（/guild permission，决定在公会内谁能执行某操作）互相独立、同时生效。例如玩家拥有 guild.kick 权限，但公会内 kick 门槛设为 2（管理员），则普通成员仍无法踢人。

开发者 API 与事件

接入方式：软依赖 depend / softdepend: [Guild]，通过 GuildAPI 或 Bukkit 事件监听即可。

GuildAPI api = GuildAPI.getInstance();          // onEnable 后可用
if (GuildAPI.isApiReady()) { ... }              // 就绪检查
GuildData guild = api.getPlayerGuild(uuid);     // 只读数据视图

事件（com.guild.api.event）

事件可取消触发时机
GuildCreateEvent ✅ 创建公会前；监听器可 setGuildName / setGuildTag 改名改标签，对所有创建路径（命令 / GUI / API）生效
GuildJoinEvent✅成员加入前（申请批准、邀请接受、直接加入均触发）
GuildLeaveEvent✅成员离开前（仅在线玩家触发）
GuildKickEvent✅成员被踢出前
GuildDisbandEvent❌公会解散成功后
GuildLevelUpEvent❌等级提升后（旧等级 → 新等级）

3.0.8 重要变更：事件触发点已统一下沉至 GuildManager。经任何路径（命令、GUI、API）操作都恰好触发一次事件；第三方插件不应再自行补发。所有非异步事件均在主线程触发。

监听示例

@EventHandler
public void onGuildCreate(GuildCreateEvent event) {
    if (event.getGuildName().length() < 2) {
        event.setCancelled(true);
        event.getPlayer().sendMessage("公会名太短");
        return;
    }
    // 也可在此改名 / 改标签
    event.setGuildTag("[" + event.getGuildName() + "]");
}

数据库说明

双后端

config.yml → database.type 选 sqlite（默认，单文件在 plugins/Guild/ 内）或 mysql（host / port / pool-size / connection-timeout 全部真实生效，InnoDB + utf8mb4）。

连接池

HikariCP（已 shade 重定位至 com.guild.lib.hikari，不与其他插件冲突）。

表结构

表名内容
guilds公会主数据
guild_members成员 / 角色 / 贡献 / 禁言 / 昵称
guild_permissions公会内权限门槛
guild_banks银行余额
player_currency公会币余额

写入策略

  • saveGuild 事务化：主数据 upsert、成员表先删后插（杜绝离会成员复活，3.0.8）、权限与银行 upsert
  • 解散时异步级联删除
  • 重命名公会会同步迁移四张关联表（事务）

性能与线程安全设计

3.0.8 完成的主要性能优化：

  • 主线程零数据库 I/O：全部公会写操作进入异步保存队列（约 2.5 秒批量落盘）；解散删库、账户初始化等均为异步任务
  • 玩家名缓存：高频 UUID→名字解析统一走缓存，避免 Bukkit.getOfflinePlayer() 触发的磁盘读档
  • 内存防泄漏：入会申请 / 邀请定时过期清理；银行历史记录每人限 50 条；玩家下线清理挂起的聊天输入与 GUI 状态
  • 线程安全：核心索引使用 ConcurrentHashMap / CopyOnWriteArrayList；升级循环、禁言状态等均有边界防护；异步聊天监听器内的公会操作统一切回主线程

开发者 API核心功能常见问题

常见问题 FAQ

本页收录 Guild 使用与运维中最常见的疑问。更多细节见 核心功能详解 与 配置文件与数据库。

兼容性与依赖

Q1：插件支持哪些服务端？Folia 能用吗？
A：Spigot / Paper / Purpur / Folia 全支持，Minecraft 1.8 ~ 26.2+。plugin.yml 已声明 folia-supported: true。

Q2：没装 Vault 能用吗？
A：能。Vault / PlayerPoints / PlaceholderAPI 均为软依赖，缺失时自动降级；默认货币为内置公会币（GUILD_COIN），开箱即用且重启不丢数据。

Q3：占位符不显示值？
A：确认已安装 PlaceholderAPI 且 Guild 在其之后加载（软依赖已自动处理）；无公会玩家变量返回空属正常设计。

数据与扣费

Q4：创建公会扣了几次钱？
A：3.0.8 起命令、GUI 铁砧、API 三条路径全部统一为 createGuild 内单次扣费，不再预扣 / 退款。

Q5：被踢的玩家为什么不会再“复活”？
A：3.0.8 起 saveGuild 在事务内先清空该公会成员行再批量插入，离会成员的数据库记录同步删除。

Q6：GUI 里改了职位 / 昵称 / 踢人，重启会丢吗？
A：不会。3.0.8 起所有 GUI 写操作即时进入异步保存队列落库。

Q7：重命名公会会丢成员或银行余额吗？
A：不会。3.0.7 起 renameGuild 原地迁移内存索引与四张关联表，不重复扣创建费。

权限与银行

Q8：如何阻止普通成员取款？
A：bank.yml → withdraw-permission: OFFICER（默认已是）；或用 /guild permission 调整任意操作的最低职位门槛。

Q9：Bukkit 权限和公会内职位门槛有什么区别？
A：Bukkit 权限节点（如 guild.kick）决定玩家能否使用某功能；公会内职位门槛（/guild permission kick 2）决定在公会内谁能执行该操作。两者同时生效，需都满足。

升级与经验

Q10：升级一下子就满级了 / 经验公式配错怎么办？
A：3.0.8 起等级公式计算结果 ≤ 0 时直接跳出升级循环，杜绝瞬间刷满级；请检查 experience.yml → level-formula.base 是否误配为 0。

Q11：怎么调整某些方块 / 怪物不给经验？
A：在 experience.yml 的 no-exp-blocks / no-exp-mobs 黑名单中添加即可。

配置版本

Q12：提示“配置文件版本较旧”要怎么办？
A：无需处理。插件会自动用默认值补齐新配置项，数据不受影响；配置文件版本自 3.0.7 起保持 1.3。

Q13：改了配置要重启吗？
A：不需要。/guild reload 可热重载全部配置文件与语言包。

Q14：哪些配置项改了没用？
A：见 配置文件与数据库 的「预留配置说明」——冷却时间、银行利息、周榜奖励、自动解散等目前尚未接入业务逻辑。
