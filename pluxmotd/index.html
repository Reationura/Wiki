PluxMotd Wiki — 总览

全版本通用的服务器列表美化插件 · 当前版本 v1.0.0

PluxMotd 是一款全版本通用的服务器列表美化插件：单个 JAR 同时支持 Minecraft Java 1.8 - 26.x 的 Spigot / Paper / Purpur 服务端，安装后无需按版本选择任何文件。

插件启动时会自动检测服务端版本并选择对应的内部适配器（Legacy / Modern / Latest），控制台输出醒目的中文横幅，包含检测到的版本、所选适配器与能力开关。

功能模块一句话说明
双行 MOTD两行分开配置、每行独立对齐，支持 RGB / 渐变 / 彩虹
服务器图标正常 / 维护两套 64×64 PNG，缺失自动回退
维护模式一键开关、重启保留、白名单放行、进入拦截与提示全可定制
假人数固定 / 随机 / 真实偏移 / 百分比四种模式，维护期可独立配置
全中文配置注释、消息文案、控制台输出、启动横幅全部中文

快速上手

  1. 将 PluxMotd.jar 放入服务端的 plugins 文件夹并重启服务端。
  2. 编辑 plugins/PluxMotd/config.yml，填写 motd.normal.line1 / line2 等文案（支持 RGB / 渐变 / 彩虹）。
  3. 执行 /pluxmotd reload 使配置生效；用 /pluxmotd motd preview 在聊天栏预览效果。
  4. 需要临时关闭服务器时执行 /pluxmotd maintenance on，恢复时 off。

文档版本：对应 PluxMotd v1.0.0。

功能介绍

本文档面向希望完整了解 PluxMotd 能力的用户与服务端管理员。配置项细节见 配置文件详解。

1. 核心功能：双行 MOTD

Minecraft 服务器列表的 MOTD 固定为两行。PluxMotd 采用分行配置，直观且不需要转义换行符：

motd:
  normal:                     # 正常状态显示
    line1: "<gradient:#FF6A00:#FFD200><bold>PluxMotd 服务器</bold></gradient>"
    line2: "<color:#00AAFF>欢迎来到这里，一起玩吧！</color>"
    line1-align: CENTER       # 第一行居中
    line2-align: CENTER       # 第二行居中

  maintenance:                # 维护模式开启时显示
    line1: "<color:#FFAA00><bold>服务器维护中</bold></color>"
    line2: "<gray>我们正在努力，请稍候再来……</gray>"

要点：

  • line1 / line2 各占一行，不需要再写 \n；line2 留空则只显示一行。
  • 每行可独立配置对齐方式（见第 4 节）。
  • 正常 / 维护 / 旧客户端三套文案互相独立，随时切换维护模式即可整套替换。
  • 向下兼容旧写法：如果配置仍是“一个字符串 + \n”或字符串列表，插件会自动识别并拆回两行，老配置文件可直接沿用升级。

/pluxmotd motd preview 可以在聊天栏同时预览“正常状态”与“维护状态”两套双行 MOTD 的实际效果。

2. 文本格式系统

所有文本字段（MOTD、踢出提示、消息文件）使用同一套格式语言，可自由混用三种写法。

2.1 MiniMessage 风格标签

标签作用示例
<color:#RRGGBB>指定 RGB 颜色<color:#00AAFF>蓝色文字</color>
#RRGGBB（作为标签名）同上，简写<#FF5555>红色</#FF5555>
<颜色名>16 种命名颜色<red> <gold> <gray> <aqua> 等，也支持 orange、light_purple 等别名
<gradient:#A:#B> / <gradient:#A:#B:#C>在多个颜色站点之间平滑渐变<gradient:#FF0000:#00FF00>渐变标题</gradient>
<rainbow>整段文字覆盖全彩虹色环<rainbow>彩虹</rainbow>
<bold> <italic> <underlined> <strikethrough> <obfuscated>粗体 / 斜体 / 下划线 / 删除线 / 滚动乱码<bold><italic>粗斜体</italic></bold>
<reset>清除当前所有格式—
<space:N>插入 N 个空格（排版用，见第 4 节）<space:6>
<br>在文本中强制换行—

标签支持嵌套，渐变 / 彩虹会按实际渲染字符逐字符计算颜色。

2.2 传统颜色码

  • & 或 § 开头的原版代码全部可用：&a-&f 颜色、&k 乱码、&l 粗体、&m 删除线、&n 下划线、&o 斜体、&r 重置。
  • 内联十六进制：&#RRGGBB（例：&#FF6A00），以及完整的 §x§R§R§G§G§B§B 形式。

2.3 混用规则

以上写法可以在同一条字符串里任意混排，例如：

line1: "&6&#FF6A00<gradient:#FF6A00:#FFD200>Plux</gradient> <bold>服务器</bold>"

3. 排版与对齐系统

3.1 为什么需要“对齐”

原版服务器列表对 MOTD 两行一律从最左侧开始绘制。PluxMotd 通过精确计算每行文字的近似像素宽度，在行首自动补入空格，实现视觉上的居中（CENTER）与右对齐（RIGHT）效果。

3.2 配置方式

motd:
  normal:
    line1: "..."
    line1-align: CENTER     # LEFT / CENTER / RIGHT，也可直接写中文：左 / 居中 / 右
  format:
    align-width: 220        # 对齐参考宽度（像素）
    default-align: CENTER   # 未显式指定 line*-align 时每一行的默认对齐
  • 对齐取值：LEFT 左对齐（原版行为，不补位）、CENTER 居中、RIGHT 右对齐；同时接受中文写法（“居中”、“左对齐”、“右”等）与常见缩写（MIDDLE、C、R、L）。
  • align-width（参考宽度）：对齐计算所依据的显示区域宽度。服务器列表 MOTD 区域约 220 像素，一般无需修改；若觉得整体偏左 / 偏右，微调该值即可。
  • 宽度计算规则：英文、数字按原版字体逐字符宽度累加，中文等全角字符按 8 像素计算，粗体字符会额外加宽——因此中英文混排、加粗与否都能得到正确的补位。

3.3 手动微调

自动补位为近似值（个别资源包字体可能有 1-2 像素偏差）。需要绝对精确时：

  • 用 <space:N> 在行首 / 行中手动插入空格微调；
  • 或为该客户端配置 motd.legacy 传统文案，亲手控制每一个字符。

4. 服务器图标

icon:
  enabled: true
  normal-path: "icon.png"               # 相对 plugins/PluxMotd/，也可写绝对路径
  maintenance-path: "maintenance-icon.png"
  fallback-to-default: true             # 维护图标缺失时回退使用普通图标
  • 图片要求：PNG 格式，恰好 64×64 像素，不符合会自动跳过并使用原版图标（不会报错刷屏）。
  • 正常与维护两套图标独立加载；更换文件后执行 /pluxmotd icon reload 即可生效，无需重载整个配置。
  • 维护模式开启时，列表自动展示维护图标（可通过 maintenance.use-maintenance-icon 关闭该联动）。

5. 维护模式

5.1 开关与持久化

  • /pluxmotd maintenance on | off | status 随时切换，无需改配置、无需重启。
  • 实时状态写入 data.yml，服务端重启后保持原样（首次启动的初始值由 maintenance.enabled 决定）。
  • 状态落盘在后台异步完成，主线程零阻塞。

5.2 谁能进、谁被拦

被拦截的玩家在登录阶段直接看到自定义踢出提示（不占用加载时间）。放行优先级：

  1. 拥有 pluxmotd.bypass 权限的玩家（OP 默认拥有）；
  2. maintenance.whitelist 白名单中的玩家名或 UUID（带不带 - 的 UUID 均可识别）；
  3. 控制台 / 拥有权限的 OP 永远可进。

封禁、服务器已满等其他拒绝原因不受影响、不会被覆盖。

5.3 踢出提示支持分行

maintenance:
  kick-message:
    line1: "<red><bold>服务器正在维护中！</bold></red>"
    line2: "<gray>预计很快恢复，请稍后再试。</gray>"

同样兼容旧版“单字符串 + \n”写法，支持全部颜色格式与 RGB。

5.4 维护期间的整套联动

维护模式开启时可逐项切换（每一项目前独立开关）：

配置项作用
use-maintenance-motd列表 MOTD 切换为维护文案
use-maintenance-icon列表图标切换为维护图标
use-maintenance-fake-players人数切换为维护专用假人数
show-maintenance-motd-to-alltrue：所有人看到维护 MOTD；false：列表照常显示正常 MOTD，仅在进入时拦截（“低调维护”）

6. 假人数系统

fake-players:
  enabled: true
  mode: "FIXED"                 # FIXED | RANDOM | REAL_OFFSET | PERCENTAGE
  random-refresh-seconds: 30    # RANDOM 模式的刷新周期
  normal:       { ... }         # 正常状态的人数配置
  maintenance:  { ... }         # 维护状态的人数配置（enabled: true 时独立生效）
模式行为关键参数
FIXED 固定永远显示设定值online、max
RANDOM 随机在区间内随机，间隔 random-refresh-seconds 秒重掷；设为 0 则每次列表刷新都随机random.min-online / max-online / min-max / max-max
REAL_OFFSET 真实偏移显示 真实在线 + online-offset、真实上限 + max-offsetreal-offset.online-offset / max-offset
PERCENTAGE 百分比显示 真实在线 × online-percent ÷ 100（150 = 显示 1.5 倍）percentage.online-percent
  • 结果自动裁剪在 0 ≤ 在线 ≤ 上限 的合法范围内，绝不会出现“在线人数大于上限”的穿帮。
  • 正常 / 维护各有一套独立模式与参数，互不干扰。

7. 性能与安全设计

  • 列表刷新零开销：所有 MOTD 文本在配置加载时预先渲染并缓存；每次服务器列表请求只是从内存取字符串，不读文件、不查数据库、不发网络请求、不解析格式。
  • 主线程不阻塞：维护状态写盘在异步线程完成；图标只在加载 / 重载时读取一次。
  • 异常隔离：处理列表请求与拦截登录的逻辑全部有保护，任何意外只记录日志，绝不影响服务端运行。
  • 无前置依赖：不需要安装任何其他插件或库，不注入、不修改游戏文件。

8. 已知限制

  • 对齐为空格补位模拟，极端字体资源包下可能有 1-2 像素偏差（可手动微调，见 3.3）。
  • 1.8 - 1.15 客户端没有真 RGB，这是游戏本身的能力限制。
  • MOTD 单行长度受原版协议约束（约 59 个字符 / 220 像素），超出会被客户端截断。
  • 若未来 Minecraft 大版本造成服务端 API 重大变更，需等待插件更新对应适配层。

配置文件详解

插件首次启动后会在 plugins/PluxMotd/ 下生成配置文件。修改后使用 /pluxmotd reload 热重载即可。

config.yml 结构总览

motd:
  normal / maintenance     双行 MOTD（line1、line2、line1-align、line2-align）
  format                   排版设置（align-width、default-align）
  legacy                   旧客户端（1.8-1.15）专用文案，结构与 normal 相同
    enabled                开关（默认关闭 = 自动降级）
  fallback-color           旧客户端 RGB 统一折叠成的颜色；留空 = 逐字符取最近 16 色
icon:                      图标（enabled、normal-path、maintenance-path、fallback-to-default）
fake-players:              假人数（enabled、mode、random-refresh-seconds、normal、maintenance）
maintenance:               维护模式（enabled、whitelist、kick-message、四项联动开关）
debug:                     输出调试日志（排障用）

motd 段落

motd:

    line1: "<gradient:#FF6A00:#FFD200><bold>PluxMotd 服务器</bold></gradient>"

messages.yml

每一条管理员 / 玩家提示都是独立键值，前缀 prefix 也可修改。主要键：

键场景

data.yml

由插件自动维护，无需手动编辑。用于保存维护模式的实时状态，服务端重启后自动恢复。

重载的“防呆”设计

  • 每次 reload 会整体重新解析配置并原子替换：解析失败时保留上一份正常配置并在控制台提示，改坏一个字母绝不会让线上 MOTD 消失。
  • data.yml 由插件自动维护，无需手动编辑。

版本兼容与自动降级

单 JAR 全版本的原理

插件内部按服务端版本自动选择三种适配器之一（用户在启动横幅中可以看到选择了哪个）：

适配器覆盖版本RGB / 渐变说明
LegacyAdapter1.8 – 1.15自动降级 16 色仅使用老 API，绝不崩溃
ModernAdapter1.16 – 1.20完整支持（§x 十六进制）原生真彩
LatestAdapter1.21 – 26.x完整支持Paper 服务端自动尝试组件 MOTD，失败则回退

玩家客户端的版本独立判断：新客户端看到完整 RGB，老客户端看到降级版本，同一份配置同时服务所有玩家。

支持范围总览

项目说明
服务端核心Spigot / Paper / Purpur
Minecraft 版本1.8 - 26.x（单个 JAR 通吃，无需按版本选择文件）
前置依赖无（不需要安装任何其他插件或库）

降级规则细节

  • 渐变 / 彩虹在 1.8 - 1.15 上呈现为逐字符最接近的 16 色阶梯，层次感保留。
  • 设置 motd.fallback-color 后，旧客户端的所有彩色统一折叠为该单一颜色（更整洁）。
  • 配置 motd.legacy.* 后，旧客户端直接看到你手写的传统文案（完全可控）。

适配器选择建议

场景建议
混合客户端环境直接使用默认配置，插件自动按每个客户端版本渲染，无需任何额外设置
追求精致旧版效果开启 motd.legacy.enabled，手写一套传统文案，让 1.8 - 1.15 客户端完全可控
统一整洁风格设置 motd.fallback-color 为服务器主色调，旧客户端的所有彩色折叠为单色

已知限制

  • 对齐为空格补位模拟，极端字体资源包下可能有 1-2 像素偏差。
  • 1.8 - 1.15 客户端没有真 RGB，这是游戏本身的能力限制。
  • MOTD 单行长度受原版协议约束（约 59 个字符 / 220 像素），超出会被客户端截断。
  • 若未来 Minecraft 大版本造成服务端 API 重大变更，需等待插件更新对应适配层。

常见问题 FAQ

本页收录 PluxMotd 使用与运维中最常见的疑问。更多细节见 功能介绍 与 配置文件详解。

配置与重载

Q：改了 config.yml 但列表没变化？
A：执行 /pluxmotd reload。看到“重载成功”才会生效；若提示失败，控制台会指出出错位置，且线上显示保持原样不受影响。

Q：reload 会不会把线上显示搞崩？
A：不会。每次 reload 都整体重新解析并原子替换——解析失败时保留上一份正常配置并在控制台提示。

排版与对齐

Q：居中后感觉有点偏？
A：自动补位基于近似像素宽度。整体偏了调 motd.format.align-width（如 210 / 230）；单行微调使用 <space:N>。

Q：中英文混排会不会算错宽度？
A：不会。英文 / 数字按原版字体逐字符宽度累加，中文等全角字符按 8 像素计算，粗体字符额外加宽——都能正确补位。

服务器图标

Q：图标一直不显示？
A：确认 PNG 恰好 64×64、文件名与配置一致、放在 plugins/PluxMotd/ 下。/pluxmotd status 会显示图标当前状态。

Q：更换图标需要重载整个配置吗？
A：不需要。/pluxmotd icon reload 仅重新读取图标即可。

版本与降级

Q：老玩家会不会看到 <color:...> 这样的乱码标签？
A：不会。所有标签在发送前已渲染成颜色代码；1.8 - 1.15 客户端收到的是自动降级或你配置的 legacy 文案。

Q：1.8 - 1.15 客户端能看到渐变吗？
A：能看到，但会呈现为逐字符最接近的 16 色阶梯。这是游戏本身的能力限制；如要统一风格可设置 motd.fallback-color。

Q：MOTD 太长被截断怎么办？
A：MOTD 单行受原版协议约束（约 59 个字符 / 220 像素），超出会被客户端截断。请精简文案或拆到第二行。

维护模式

Q：维护模式会不会挡住 OP？
A：不会。OP 默认拥有 pluxmotd.bypass；也可把普通玩家写进 maintenance.whitelist（支持玩家名和 UUID，UUID 带不带 - 均可识别）。

Q：重启后维护模式状态丢失吗？
A：不丢失，状态实时保存在 data.yml，服务端重启后自动恢复。

Q：能不能列表显示正常 MOTD、但实际拒绝进入？
A：可以。将 maintenance.show-maintenance-motd-to-all 设为 false（“低调维护”）。

Q：维护模式会不会覆盖封禁、服务器已满等其他拒绝原因？
A：不会。其他拒绝原因不受影响、不会被覆盖。

假人数

Q：假人数会超过上限导致穿帮吗？
A：不会，任何模式下在线人数都会被限制在 0 与显示上限之间。

Q：随机模式的刷新周期怎么调？
A：修改 fake-players.random-refresh-seconds（秒）。设为 0 则每次列表刷新都重新随机。

性能与编码

Q：列表刷新会不会很耗性能？
A：不会。所有 MOTD 文本在配置加载时预先渲染并缓存；每次服务器列表请求只是从内存取字符串，不读文件、不查数据库、不发网络请求、不解析格式。

Q：控制台中文日志乱码？
A：仅可能出现在 Windows 老版本服务端的控制台窗口（GBK 编码）。将控制台切换为 UTF-8（chcp 65001）即可；配置文件与玩家看到的消息不受影响。

Q：出问题怎么排查？
A：开启 config.yml 的 debug: true，插件会输出更详细的日志；配合 /pluxmotd status 查看当前适配器与各模块状态。
